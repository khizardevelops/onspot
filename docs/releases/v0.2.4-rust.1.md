# onspot 0.2.4 — Rust core preview

A preview build of onspot running on its new Rust core. It looks and works like 0.2.4; underneath,
settings, practice, feedback, translations, history, insights, export, sync and usage tracking now
run in Rust, shared by every platform. Published as a pre-release: the latest stable version stays
[0.2.4](https://github.com/khizardevelops/onspot/releases/tag/v0.2.4).

## What changed underneath

- **One Rust core on every platform.** The web app, the desktop apps and Android run the same core:
  in the browser as WebAssembly, on desktop and Android in the app itself.
- **One database connection.** The desktop and Android apps open their database once, from Rust,
  instead of through two separate SQLite libraries.
- **Usage counts every request.** Feedback, translations, word meanings and new prompts all show
  up under **Settings → Usage**, with the provider's live limits where it reports them.
- **Gentler on rate limits.** Requests wait for room under your provider's per-minute limit (and
  say so in Practice) or move to a fallback model, instead of failing.
- **Sync notices every change.** Takes, renames and deletions all count as local changes, so a
  sync never replaces new practice with an older cloud copy.
- **A local LLM server gets its own key**, never another provider's.

## Known issues

- **A preview.** It has been tested on Linux desktop, Android and in the browser; Windows and macOS
  builds come from CI and have not had a hands-on pass. Please report anything that looks wrong.
- **The installers are not code-signed yet.** On macOS, you may need to allow the app in
  **System Settings → Privacy & Security**. On Windows, SmartScreen may ask you to confirm.
- **Recording stops at 60 seconds.**

Download only from the official
